Chapter 5 · Vector Data: TF-IDF Vectors, GPU Semantic Search & Classical ML¶

So far in Part I, we've worked with two classic data types:

  • Tabular Data (Ch. 1–2): Spreadsheets with named columns (rooms, income, latitude).
  • Image Data (Ch. 3–4): 2D grids of pixel brightness (28 × 28).

Now let's tackle the third major data type in modern AI: Vector Data (Embeddings) — how we turn unstructured text (news articles, documents, chat messages) into lists of numbers (vectors) so your Vulkan GPU can search by meaning and classify topics!

In this chapter, we'll use 7,600 real AG News articles across 4 topics (World, Sports, Business, Sci/Tech):

  1. Turn Text into Vectors (TF-IDF): Convert raw English sentences into L2-normalized 2,000-D feature vectors (no data leakage!).
  2. Build a 5-Line Vulkan GPU Vector Database: Search 6,000 articles in < 1 ms using GPU Cosine Similarity (query @ db.T + vnp.top_k) — the exact core of modern RAG & semantic search!
  3. Visualize the Vector Space (vkvis.UMAP): Project high-dimensional text vectors into 2D on GPU to see the 4 topic islands.
  4. Classical ML Topic Classification Bake-Off (vklearn): Compare Bag-of-Words vs. TF-IDF vs. PCA (Latent Semantic Analysis) + KNN & LogisticRegression.
  5. Hit the "Synonym Wall": See why classical word-count vectors think "car" and "automobile" have 0.00 similarity — setting up Chapter 6 (vktorch Neural Embeddings)!

Step 1: Turning Sentences Into Vectors (Bag-of-Words → TF-IDF)¶

A GPU can't multiply English words — it needs vectors of numbers.

  1. Bag-of-Words (BoW): Pick the top 2,000 words from the training articles and count how many times each word appears in an article.
  2. TF-IDF (Term Frequency × Inverse Document Frequency): Common filler words like "the", "with", and "said" appear in every topic and add noise. TF-IDF multiplies each word count by log(N / doc_freq) so rare, topic-defining words ("semiconductor", "quarterback", "inflation", "treaty") stand out!
  3. L2 Normalization: Scale every article vector to length 1.0 on GPU (v / ||v||) so short headlines and long paragraphs are compared fairly!

TOKEN_RE = re.compile(r"[a-z]{3,}")
STOP_WORDS = {
    "the", "and", "for", "that", "with", "from", "this", "are", "was", "were",
    "has", "have", "had", "its", "his", "her", "their", "but", "not", "will",
    "would", "about", "into", "over", "after", "more", "than", "new", "said",
    "says", "two", "one", "out", "who", "they", "been", "all", "can", "year",
}

def tokenize(text: str):
    return [w for w in TOKEN_RE.findall(text.lower()) if w not in STOP_WORDS]

# Build vocabulary + IDF weights from TRAINING set only (zero data leakage!)
VOCAB_SIZE = 2000
doc_freq = Counter()
toks_tr = [tokenize(t) for t in texts_tr]
toks_te = [tokenize(t) for t in texts_te]
for toks in toks_tr:
    doc_freq.update(set(toks))

vocab = [w for w, _ in doc_freq.most_common(VOCAB_SIZE)]
word2id = {w: i for i, w in enumerate(vocab)}
idf = np.array([np.log((1.0 + len(toks_tr)) / (1.0 + doc_freq[w])) + 1.0 for w in vocab], dtype=np.float32)

def vectorize(tok_lists, use_tfidf=True):
    mat = np.zeros((len(tok_lists), VOCAB_SIZE), dtype=np.float32)
    for r, toks in enumerate(tok_lists):
        for w in toks:
            idx = word2id.get(w)
            if idx is not None:
                mat[r, idx] += 1.0
    if use_tfidf:
        mat = np.log1p(mat) * idf[None, :]
    # L2-normalize each row on Vulkan GPU so dot product == Cosine Similarity!
    M_g = vnp.array(mat)
    norms = vnp.sqrt(vnp.sum(M_g * M_g, axis=1, keepdims=True) + 1e-8)
    return (M_g / norms).to_numpy()

X_tr_bow = vectorize(toks_tr, use_tfidf=False)
X_te_bow = vectorize(toks_te, use_tfidf=False)
X_tr_vec = vectorize(toks_tr, use_tfidf=True)
X_te_vec = vectorize(toks_te, use_tfidf=True)

print(f"TF-IDF Vector Database shape: {X_tr_vec.shape} (float32, L2-normalized)")
print(f"Top 10 distinctive high-IDF words in vocab: {sorted(vocab, key=lambda w: idf[word2id[w]], reverse=True)[:10]}")

Step 2: Build a 5-Line Vulkan GPU Vector Database (Cosine Similarity Search!)¶

Because every article vector has length 1.0, the Cosine Similarity between a search query vector q and all 6,000 articles at once is literally a single GPU matrix multiply:

scores = q_gpu @ db_gpu.T     # 1 Vulkan GEMM!
top_ids = vnp.top_k(scores, k=3, axis=1)

That's the exact mathematical engine powering modern Vector Databases and RAG (Retrieval-Augmented Generation)! Let's query our 6,000-article Vulkan GPU Vector DB right now.

In [3]:
# Keep the 6,000-article Vector Database resident in GPU VRAM
DB_GPU = vnp.array(X_tr_vec)  # (6000, 2000)

def vector_search_gpu(query: str, top_k: int = 3):
    t0 = time.perf_counter()
    q_vec = vectorize([tokenize(query)], use_tfidf=True)  # (1, 2000)
    scores = vnp.array(q_vec) @ DB_GPU.T                  # (1, 6000) Cosine Similarity on GPU!
    top_ids = vnp.top_k(scores, k=top_k, axis=1).to_numpy()[0]
    sc_np = scores.to_numpy()[0]
    ms = (time.perf_counter() - t0) * 1000.0
    return [(int(i), float(sc_np[i]), CLASS_NAMES[y_tr[i]], texts_tr[i]) for i in top_ids], ms

queries = [
    "computer software chip security linux",
    "olympic basketball championship stadium coach",
    "stock market oil prices bank economy",
]

# Warmup
_ = vector_search_gpu(queries[0], top_k=3)

for q in queries:
    hits, ms = vector_search_gpu(q, top_k=3)
    print(f'Query: "{q}"  ({ms:.2f} ms on Vulkan GPU)')
    for rank, (_, sim, topic, txt) in enumerate(hits, 1):
        print(f"  {rank}. [sim={sim:.3f} | {topic:8s}] {txt[:92]}...")
    print()

Step 3: Visualize the 2,000-D Vector Space in 2D (vklearn.PCA + vkvis.UMAP)¶

Humans can't see 2,000 dimensions — so let's compress our TF-IDF vectors to 64 dense "topic dimensions" with GPU vklearn.PCA (classic Latent Semantic Analysis) and project a 1,600-article sample into 2D using vkvis.UMAP on Vulkan GPU! Watch the 4 news topics separate into colorful islands.

Step 4: Classical ML Topic Classification Bake-Off on Vulkan GPU¶

Now let's classify all 1,600 held-out test articles into World, Sports, Business, or Sci/Tech using 4 Classical ML approaches on our Vulkan GPU:

  1. Raw Bag-of-Words + GPU Cosine KNN (k=11) (before TF-IDF weighting!)
  2. TF-IDF (2,000-D) + GPU Cosine KNN (k=11)
  3. TF-IDF + GPU PCA (64-D LSA) + OvR LogisticRegression
  4. TF-IDF (2,000-D) + GPU Nearest-Centroid + OvR LogisticRegression (direct on 2,000-D TF-IDF? Let's use fast GPU Ridge multi-class / 128-D PCA + OvR LogisticRegression!)

Step 5: The Famous "Synonym Wall" (Why We Need Neural Embeddings in Ch. 6!)¶

TF-IDF is fast and strong when two articles share the exact same words. Watch what happens when two sentences mean the exact same thing using DIFFERENT words (synonyms):

pairs = [
    ("fast car highway driver",        "quick automobile freeway motorist"),
    ("laptop computer software chip",  "notebook machine program processor"),
    ("basketball game stadium coach",  "basketball match stadium player"),
]
print("TF-IDF Cosine Similarity on Synonym Pairs vs. Exact-Word Overlap:")
for a, b in pairs:
    va = vectorize([tokenize(a)], use_tfidf=True)[0]
    vb = vectorize([tokenize(b)], use_tfidf=True)[0]
    sim = float(np.dot(va, vb))
    print(f'  "{a}"  vs  "{b}"  ->  TF-IDF sim = {sim:.3f}')

Key Takeaways¶

  • Vector Data = turning unstructured text into geometry: With L2-normalized vectors, a Vulkan GPU Vector Database is literally 1 matrix multiply (query @ db.T) + top_k — searching 6,000 articles in ~1 ms!
  • TF-IDF beats raw Bag-of-Words by down-weighting filler words, and TF-IDF + GPU Ridge hits ~85%+ topic accuracy in seconds.
  • The Synonym Wall: Look at the output above — TF-IDF gives 0.000 similarity to "fast car highway driver" vs. "quick automobile freeway motorist" because it only matches exact spelling!
